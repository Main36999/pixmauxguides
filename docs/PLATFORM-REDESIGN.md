# Platform redesign (design stage)

Branch: `design/platform-redesign`. Visual implementation of the whole site
in the real build; no backend. Nothing here is committed, pushed or deployed
without the owner's approval.

## Preview it locally

```
npm run preview
```

Builds the site into `.preview/` (gitignored) with the normal pipeline minus
the `verify` gate, then serves it at http://localhost:4173/. It never writes
`dist/`, `.build/` or any tracked file. Stop it with Ctrl+C.

- `npm run preview -- --build-only` builds without serving.
- http://localhost:4173/__preview/sign-in shows the header signed in as a
  demo account; `/__preview/sign-out` signs out. Netlify Functions don't run
  locally, so every other `/api/*` call answers 503.
- Pages with sample states show a **Preview state** switch (bottom right),
  or take `?state=loading|empty|error`.
- Any page opened with `?preview-auth=demo` is shown signed in as the demo
  account (also inside a framed page, where the cookie isn't sent).
- Review switches for screenshots, on pages that load `/showcase.js`:
  `?open-nav=explore|learn|resources` opens a header panel;
  `?open-menu=1&expand=explore|learn|resources` opens the phone menu;
  `/styleguide?open=signin` opens the log-in dialog; `/?tab=designers`
  opens the homepage on its Designers tab; `?fill-search=word` types a
  query into the page's search; `?open-scope=header|discover` opens a
  search box's category list; at 640px and narrower, `?tray=open` presses
  the header's search button (the tray under the bar); on the homepage the
  button only shows past the page's own search, so use
  `?tray=open#feed-projects`, and `?tray=open-then-top#feed-projects` then
  scrolls back to the top, which closes it again.
- The search (header and discovery blocks) is one component with a
  category: Projects, Designers or Guides. It opens
  `/search?s=…&scope=…`. Guides, and any URL without a scope, is the real
  guide and palette search; Projects and Designers list the sample set.
- The header search is in the bar from 641px up. On the homepage,
  `/projects/` and `/designers/` it appears only once the page's own search
  has scrolled up under the header. At 640px and narrower it is a search
  button that opens the search as a tray under the bar (on those three
  pages the button waits the same way). Without JavaScript the phone's
  button is a link that opens the tray by `:target`.

## What is real and what is a demonstration

| Area | Status |
| --- | --- |
| Header, footer, design system (`src/styles/platform.css`) | Real: every page |
| Homepage hero | Real, unchanged |
| Homepage discovery block and gallery | **Demo data** below the real hero |
| Guides, roadmap, colors, palettes, fonts, search, about, contact, legal, account | Real content, restyled |
| `/projects/`, `/projects/<slug>`, `/designers/`, `/designers/<handle>` | **Demo**: sample projects and designers |
| `/studio/` (dashboard, projects, share flow, profile, settings) | **Demo**: nothing is saved or uploaded |
| `/report`, `/moderation/` | **Demo**: nothing is sent |
| `/styleguide` | Design system reference |

Every demo page carries a yellow **Design preview** bar, `noindex, nofollow`,
and is left out of `sitemap.xml`. Every sample project and designer carries a
**Demo** badge. The sample data is `src/data/showcase-demo.json`; its cover
artwork is generated by `src/build/showcase-art.js` from bpozz palettes, so no
one's real work is shown.

## Where things live

| File | What |
| --- | --- |
| `src/styles/platform.css` | Tokens, buttons, header, menus, footer, shared components, harmonisation of the older pages |
| `src/styles/showcase.css` | Gallery, project, profile, studio, share flow, report, moderation, styleguide |
| `src/build/showcase.js` | Writes the demo pages and the homepage discovery region |
| `src/build/showcase-data.js` | Loads and checks the demo data; newest-first and most-recent-designer orders |
| `src/client/showcase.js` | Browser-only interactions of the demo pages |
| `partials/header.html`, `partials/footer.html` | The new header and footer |
| `scripts/dev/preview.js` | The local preview build and server |

## Before this can ship

- The output gate (`scripts/qa/approved-output.json`) and the QA baselines
  need the owner's approval after reviewing the output diff.
- The committed `guide/*.html` pages must be regenerated so
  `src/build/guide-template.test.js` matches again.
- The demo pages must be removed or replaced by the real features before a
  production launch.
