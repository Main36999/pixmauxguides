# BPOZZ — Phase 6 Handoff: Guides Collection + Homepage Transition

Status: **implemented and validated, not committed, not pushed.**

---

## 1. Phase 6 objective

Move BPOZZ from "the homepage is the guide archive" to a resource-platform structure:

- **Homepage = discovery.** Featured Guides, Popular Tokens, Latest Palettes.
- **Collection pages = browsing.** A dedicated Guides collection at `/guides`, joining the existing `/tokens` and `/palettes`.
- **Detail pages = consuming.** `/guide/<slug>`, `/category/<slug>`, `/tokens/<slug>`, all unchanged.

Scope was limited to the approved decisions. No new resource types, content, taxonomy, Search changes, Firebase changes or visual redesign.

## 8. app.js routing fix

Before, `var isHomePage = !!gridRoot;` gated both grid rendering and homepage legacy hash routing. Removing the grid from the homepage would have silently broken the legacy routes.

After:

```js
var hasGuideGrid = !!gridRoot;   // guide grid page (/guides)
var isHomePage = !!homeView;     // homepage only (#home-view exists only in index.html)
```

| Responsibility | Flag |
|---|---|
| `render()` (grid, count, empty state) | `hasGuideGrid` |
| Level filter + `#reset-filters` listeners | `hasGuideGrid` |
| `renderLoadError()` | `hasGuideGrid` |
| "Loading guides…" state | `hasGuideGrid` |
| `data-jump-category` delegate (dead handler, guard only) | `hasGuideGrid` |
| `handleRoute()`: `#/guide/<id>`, `#/about\|contact\|privacy\|terms`, `#roadmap` | `isHomePage` |

- **Unknown-guide fallback:** `location.replace(exists ? "/guide/" + id : "/guides")`. It was `"/index.html#guides"`.
- **`guides.json` fetch** is intentionally still unconditional. Guide pages' related-guides rail and the homepage `#/guide/<id>` existence check both need it (see §19).
- Comments near the changed guards were updated to describe the new flags. There was no other cleanup.

**Verified behavior:**
- Homepage (no `#grid-root`): all legacy routes work.
- `/guides`: grid and filters work; `#/guide/g6`, `#/about` and `#roadmap` do nothing there (no redirect, no title change).
- Other pages: unchanged.

## 19. Deviations from the Phase 6 prompt

1. **Baseline source.** The prompt named `bpozz-web-phase-5.zip`. Implementation used the Phase 5 checkpoint repository (HEAD `47964ad`, tag `phase-5-complete`), whose working tree was verified byte-identical to that zip. Re-extracting the original zip would have discarded the approved checkpoint commit and tag.
2. **`twitter:url`.** Required by the prompt for `/guides`, but no existing page uses it. It was added only on `/guides`; no other page's metadata was changed.
3. **`#toolbar` breadcrumbs.** Their ListItem was named "Mobile App Design", a category. Retargeting only the URL to `/guides` would have labeled the Guides collection "Mobile App Design" in search results. The `item` was changed to `https://bpozz.com/guides` and the `name` to "Guides" on those 3 pages. The alternative (pointing them to `/category/mobile`) was not used because the prompt specified `/guides`.
